# Заявки в Google Таблицю — налаштування

Код уже готовий. Лишається Google-сторона: сервісний акаунт, доступ до таблиці, три змінні
в `.env`. Разом ~15 хвилин, робиться один раз.

Поки змінних немає — інтеграція просто вимкнена: заявки йдуть у Telegram, у логах один
`console.warn`. Нічого не ламається.

---

## 1. Таблиця і рядок заголовків

Створи таблицю на Google Диску. У першому рядку аркуша — рівно ці сім заголовків, у цьому
порядку:

| A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|
| Ім'я | Телефон | Пошта | Дата, час | Джерело | UTM | Квиток |

Код заголовки **не створює і не перевіряє** — він лише дописує рядки знизу. Якщо заголовків
не буде, перша ж заявка стане першим рядком таблиці.

Назву аркуша (вкладка внизу) став латиницею, напр. `Leads`, і вкажеш її потім у
`GOOGLE_SHEETS_TAB`. Кирилиця в цій змінній працює лише якщо `.env` збережено в UTF-8 —
WinSCP за замовчуванням пише в ANSI/cp1251 і перетворює назву на биті байти, після чого
Sheets віддає `400 Unable to parse range`.

Хочеш назву українською — назви вкладку рівно `Заявки` і взагалі не додавай
`GOOGLE_SHEETS_TAB` у `.env`: це значення за замовчуванням, воно зашите в коді, який
гарантовано в UTF-8.

**ID таблиці** — з адресного рядка:

```
https://docs.google.com/spreadsheets/d/1AbC...XyZ/edit
                                      ^^^^^^^^^^ оце і є ID
```

Без `/d/`, без `/edit`, без `#gid=0`. Зазвичай рівно 44 символи, лише літери, цифри, `-` та `_`.
Перевірити, що в `.env` не заліз зайвий символ (лапки, пробіл, `\r` від редагування у Windows):

```bash
grep GOOGLE_SHEETS_ID .env | cat -A | sed -E 's/=[A-Za-z0-9_-]+/=<ID>/'
```

Чисто — `GOOGLE_SHEETS_ID=<ID>$`. Усе інше (`="<ID>"$`, `=<ID>^M$`, `= <ID>$`) треба чистити.

## 2. Google Cloud: проєкт і Sheets API

1. Відкрий https://console.cloud.google.com/
2. Угорі зліва — селектор проєкту → **New Project**. Назва будь-яка, напр. `cif26-leads`.
   Дочекайся створення і переконайся, що вибрано саме його.
3. Пошук угорі → `Google Sheets API` → **Enable**.

## 3. Сервісний акаунт і ключ

1. **APIs & Services → Credentials → Create credentials → Service account**.
2. Назва напр. `cif26-sheets-writer`. **Create and continue**. Ролі (Grant access) —
   пропусти, вони тут не потрібні: доступ дає шеринг самої таблиці, а не IAM. **Done**.
3. Клацни створений акаунт → вкладка **Keys** → **Add key → Create new key → JSON** →
   **Create**. Файл `*.json` завантажиться в Downloads.

Цей файл — пароль до таблиці. Не комітити, не кидати в чат, не слати месенджером.

## 4. Дати сервісному акаунту доступ до таблиці

Скопіюй email акаунта — виглядає як
`cif26-sheets-writer@cif26-leads.iam.gserviceaccount.com` (вкладка **Details**).

У таблиці: **Share** → встав цей email → права **Editor** → зніми галочку «Notify people»
(це не людина) → **Share**.

Без цього кроку API поверне `403` навіть при правильному ключі.

## 5. Перетворити ключ у base64

Один рядок замість багаторядкового JSON — інакше перенос рядків у `.env` гарантовано зламається.

PowerShell (Windows):

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:USERPROFILE\Downloads\ІМЯ-ФАЙЛУ.json")) | Set-Clipboard
```

bash (Linux/macOS/Git Bash):

```bash
base64 -w0 ~/Downloads/ІМЯ-ФАЙЛУ.json
```

Результат — довгий рядок без пробілів і переносів.

## 6. Змінні на сервері

`.env` лежить у `/var/www/cif26/.env`, він у `.gitignore` і `git pull` його не чіпає.

```
GOOGLE_SERVICE_ACCOUNT_B64=<рядок з кроку 5>
GOOGLE_SHEETS_ID=<ID з кроку 1>
GOOGLE_SHEETS_TAB=Заявки
```

`GOOGLE_SHEETS_TAB` можна не вказувати — тоді береться `Заявки`.

Далі — звичайний цикл оновлення:

```bash
cd /var/www/cif26 && git pull origin main && source ~/.nvm/nvm.sh && nvm use 20 && npm install && npm run build && pm2 restart cif26
```

`npm install` тут обов'язковий — додався пакет `google-auth-library`.

## 7. Перевірка

Надішли тестову заявку з сайту. Має статись усе три:

1. повідомлення в Telegram — як і раніше;
2. новий рядок унизу таблиці;
3. **жодного** `⚠️ Заявка НЕ записана в таблицю` в Telegram.

Прийшов такий алерт — у ньому вказана причина. Розшифровка:

| Текст у алерті | Що не так |
|---|---|
| `Sheets API 404` | або не той `GOOGLE_SHEETS_ID`, або таблиця не пошерена на email сервісного акаунта (крок 4). Google навмисне не розрізняє «не існує» і «не маєш доступу», щоб не видавати факт існування файлу — перевіряй обидва |
| `Sheets API 403` | Sheets API не увімкнено в проєкті (крок 2) |
| `Sheets API 400` … `Unable to parse range` | назва аркуша в `GOOGLE_SHEETS_TAB` не збігається з вкладкою в таблиці. Видно `??????` замість кирилиці — `.env` збережено не в UTF-8, див. крок 1 |
| `is not base64-encoded JSON` | у base64-рядок влізли переноси або пробіли — перероби крок 5 |
| `has no client_email / private_key` | закодовано не той файл |
| `invalid_grant` | ключ видалено в Cloud Console, або годинник сервера збився |

Алерти нема, рядка теж нема → змінні не долетіли до процесу: перевір `.env` і чи був
`pm2 restart` **після** його редагування.

## Як воно поводиться

- Telegram і таблиця пишуться **паралельно**. Таблиця впала — людина на сайті все одно бачить
  «дякуємо», бо лід уже в Telegram. Ти дізнаєшся з алерта.
- Ретраїв немає: один запит на заявку.
- Дедуплікації немає: двічі надіслана форма = два рядки.
- Усе пишеться **текстом** (`valueInputOption=RAW`), тому `+380…` лишається телефоном, а не
  перетворюється на число. Побічний ефект: «Дата, час» — теж текст, фільтр за періодом
  засобами Таблиць по ній не працюватиме. Рядки й так ідуть хронологічно.
- UTM — усі непорожні в одній комірці: `utm_source=facebook | utm_medium=cpc`. Треба буде
  розкласти на колонки — `SPLIT(F2; " | ")`.
- «Джерело» для квитків уже містить назву (`Квиток — VIP`), колонка «Квиток» дублює саму назву
  окремо, щоб зручно було рахувати зведеною таблицею.
